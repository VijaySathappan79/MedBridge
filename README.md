# MedBridge - Smart Healthcare Appointment & Medical Records System

Flutter app (Android + Web) using Firebase Authentication and Cloud Firestore.
Built for the free **Spark plan**: no Firebase Storage and no Cloud Functions needed.

## What is in this zip
`lib/`, `pubspec.yaml`, `firestore.rules`, `test/`. The `android/` and `web/`
folders are generated by Flutter in step 1 (they are not in the zip).

## Setup (one time)

1. **Generate platform folders** - open a terminal in this folder (where `pubspec.yaml` is):

       flutter create --org com.medbridge --project-name medbridge --platforms=android,web .
       flutter pub get

2. **Connect Firebase** (project must already exist, with Email/Password sign-in and Firestore enabled):

       firebase login
       flutterfire configure

   Choose your MedBridge project and tick **Android** and **Web**.
   This overwrites `lib/firebase_options.dart` with your project keys.

3. **Paste the security rules**: Firebase console > Databases & Storage > Firestore Database > **Rules** tab.
   Replace everything with the contents of `firestore.rules` and click **Publish**.

4. **Android notification setup** (needed for the notification demo):

   a. Open `android/app/build.gradle.kts` (or `build.gradle` on older projects).
      Inside `android { compileOptions { ... } }` add `isCoreLibraryDesugaringEnabled = true`
      (Groovy: `coreLibraryDesugaringEnabled true`). Then add at the end of the file:

           dependencies {
               coreLibraryDesugaring("com.android.tools:desugar_jdk_libs:2.1.4")
           }

      (Groovy: `coreLibraryDesugaring 'com.android.tools:desugar_jdk_libs:2.1.4'`)

   b. Open `android/app/src/main/AndroidManifest.xml` and add these two lines
      just above the `<application` tag:

           <uses-permission android:name="android.permission.INTERNET"/>
           <uses-permission android:name="android.permission.POST_NOTIFICATIONS"/>

   c. If the build says minSdk is too low, set `minSdk = 23` in the same gradle file.

## Run

    flutter run -d chrome        # web demo
    flutter devices              # find your phone (USB debugging ON)
    flutter run -d <device-id>   # mobile demo

Build an installable APK: `flutter build apk --release`
Build the web app: `flutter build web`

## Demo script (covers the rubric)

1. Register a **Doctor** account (e.g. in Chrome) and a **Patient** account (on the phone).
2. Patient: Home > Book Appointment > pick doctor, date, slot > Confirm -> confirmation screen + notification.
3. Doctor: Requests > Accept -> patient receives a notification.
4. Doctor: Patients > open patient > Add diagnosis and Prescription.
5. Patient: Records (see doctor's record), Prescriptions, Appointments (cancel one).
6. Close and reopen the app: you stay logged in. Profile > Logout.

## Notes and limits

- Notifications are raised by listening to Firestore, so the app must be running
  (foreground or recently backgrounded). True push while the app is closed needs
  Cloud Functions + FCM (Blaze plan).
- Medical record images are stored as small base64 strings in Firestore (max about 600 KB each).
- Appointment reminders are not included in this version.
- Create at least one doctor account before testing the patient flow.
- Firestore rules let any signed-in doctor read patient records (demo level).
  A production system would restrict this to doctors with an appointment.
